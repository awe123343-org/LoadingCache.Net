# ADR-0008: Request-triggered refresh and owned load deadlines

Accepted, 12 September 2026; admission became opt-in under [ADR0015](0015-opt-in-load-admission.md).

Refresh eligibility begins at successful publication. A later `Get` returns the still-hard-fresh old value and starts/joins one refresh; `TryGet` does neither. Offload automatic reload's synchronous prefix after reserving work, rather than blocking a hit or creating a task for every access. Configured admission is shared with cold loads; automatic refresh skips when full, explicit refresh rejects. Joiners can help start installed work. Synchronous refresh uses synchronous flight signalling, not `.Result` over an async loader.

Hard expiry hides the old value but retains a valid refresh flight for joining. Success publishes value/weight/duration and timestamps only for exact entry/epoch/flight ownership. Failure/timeout keeps the old value only until its original expiry and applies automatic retry backoff; explicit refresh bypasses backoff. Set, invalidation, eviction, clear and disposal fence old refresh work.

`LoadTimeout` starts at actual loader execution using monotonic time. A one-shot timer re-arms within BCL due-time limits. `TerminalClaimed` selects one backend outcome; cold placeholders are removed by exact identity, while refresh preserves the previous resident snapshot. Waiters receive `TimeoutException`, late results cannot publish, and faults are observed. Cache-owned async cancellation is cooperative and initiated without waiting for arbitrary token callbacks. Capture the token before timer arming, because custom `CreateTimer` may fire synchronously and dispose its CTS.

Execution completion, cancellation cleanup, timeout finalisation and promise completion are distinct. Retain the active registry/reservations until all required stages finish, including synchronous flights with no linked CTS. A running gauge may fall to zero while a reservation remains. This prevents repeated timeout/clear from bypassing limits or hiding a pending waiter from shutdown.

Retirement claims cleanup ownership/detaches resources under the engine gate, attempts timer/CTS cleanup outside it, then removes registry/reservations only after terminal signalling and cleanup attempts. Ordinary completion and final bookkeeping share the gate so a continuation's next load does not encounter its completed predecessor's reservation. Bulk completion uses a separate bounded gate, never nested with the engine gate.

Timer-disposal faults are secondary infrastructure failures: retain the selected loader/timeout result and valid value/task pairing, and saturating-count them through `MaintenanceFaults` when enabled. This includes normal, timeout, arm-after-terminal and shutdown timer cleanup. An observed failure cannot prove a custom provider actually released resources.

Once success claims terminal ownership, a later policy/expiry failure must use the claimed-failure path, not lose promise completion through a second failed CAS. Cold rollback checks exact identity/revision. Refresh rollback restores prior value/weight/time/duration/task and reconciles policy/wheel only while still owner, advancing revisions and snapshot identity to prevent ABA. Failed reconciliation removes only the owned entry. Re-arm expiry after success/rollback; secondary arm failures cannot replace the chosen outcome. Exceptional rollback must not leave a ready value paired with a failed old cold task; normal successful shared task identity stays unchanged.

Disposal fences admission/publication, detaches timers inside the gate and disposes outside it. It need not wait for loaders/listeners/cancellation callbacks; shutdown can complete still-pending promises even after a backend outcome was claimed. A synchronous factory already on the caller's stack cannot be forcibly interrupted: its promise may time out before that stack returns.

Timeout counts `LoadTimeouts`, additionally `RefreshFailures` for refresh, not `LoadCancellations`. Caller cancellation changes neither the shared outcome nor deadline. Controlled coverage includes `EngineRefreshTests`, `TimeoutEngineTests`, `TimeoutAdversarialTests`, `EngineRefreshReviewTests`, `TimeoutFinalizationTests` and bulk terminal regressions. See [semantics](../semantics.md) and [release readiness](../release-readiness.md) for contracts and measured scope.
