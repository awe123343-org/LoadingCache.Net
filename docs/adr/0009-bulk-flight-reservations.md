# ADR-0009: True bulk loading ownership

Accepted, 12 September 2026. [ADR0012](0012-notification-and-map-contracts.md) supersedes the original global prefetch stamp with a bounded per-key journal. [ADR0015](0015-opt-in-load-admission.md) makes C optional; F/K remain required for true bulk.

One backend call may serve many keys. Bound backend operations (C), owned key states across generations (F), and per-call input/output records (K) separately. True bulk requires positive F/K with K≤F; a group takes one backend reservation and one key reservation per newly owned key. Existing-flight joins take neither again.

`IBulkSyncCacheLoader`/`IBulkAsyncCacheLoader` explicitly advertise capability and inherit single-key loading. Do not detect capability by catching user `NotSupportedException`. Otherwise use bounded single-key fallback. Input is snapshotted/validated outside locks, comparer-deduplicated, and rejected after at most K+1 records; duplicates still consume input budget. Fallback and bulk mutations default to 1,024 records unless configured otherwise.

Install owned keys and reservations atomically under the engine gate, with no half-installed group on admission failure. Each key gets its own promise and start helper; any joiner can start the whole group once. Pass only missing, unowned keys to the backend. A ready read-expiry callback failing one caller must not strand an already installed shared group or release another waiter's reservation.

Snapshot and validate the full result, including missing requested keys, nulls, comparer duplicates, record limits, weights and expiry durations, before any owned publication. The map must be stable while copied. Validation is all-or-nothing; publication is independently fenced per key, not a multi-key transaction. Existing flights and concurrent mutations survive group failure. Results contain requested keys only; valid extra keys follow the journal rules in ADR0012. Capacity rejection does not prevent a waiter receiving its computed result.

Caller cancellation affects only aggregate waiting. Shared groups/single flights retain cache-owned lifetime; all callers cancelling still permits completion and caching. Mark every owned key in logical-chain reentrancy detection. Timeout revokes publication for all owned keys, but underlying work/cancellation/finalisation retains reservations.

Build additional bulk chain nodes locally, checking only the saved ambient chain because owned keys are already comparer-distinct. Use the existing weak engine owner and configured comparer. Install the completed chain once before invoking the loader and restore the saved parent once in `finally`; the owner-key node remains the responsibility of the ordinary factory scope. A construction failure must not change the ambient chain. Omitting a non-leader key or losing the outer cache's chain would turn a nested `Task.Run`/await load into a self-wait instead of the required reentrancy exception.

Synchronous owned and prefetched values create resident task views lazily through the existing entry-locked materialisation path. Async bulk promises and resident task views retain their existing behaviour. Presize result, snapshot, prepared-publication and newly owned pending-flight dictionaries only from already materialised bounded key counts. Never use the configured maximum or the loader result's `Count` as an eager capacity hint. Preserve one-pass validation, sparse/hit-heavy requests and exact entry/revision rollback ownership. `BulkAllocationSemanticsTests` covers these preservation boundaries.

Backend terminal claim and actual group completion are separate. A short completion gate signals all ≤K per-key promises and the owner consistently, setting the completed flag last. Shutdown may complete the group with `ObjectDisposedException` while a successful backend owner is blocked in a synchronous eviction listener. Normal success still follows that listener. Timer/backend arbitration remains first claimed outcome unless shutdown first actually completes the pending group.

No loader/listener/comparer, mapping cleanup, timer disposal or retirement runs under the completion gate. Precompute bounded result lookups outside it; clean failed mappings with exact ownership before signalling. TCS continuations are asynchronous; synchronous owners use their own bounded monitor completion. Never nest group and engine gates. Record exact entry/revision before fallible publication steps so failed partial initialisation cleans only its own version.

Required tests cover 100 overlapping bulk/single callers, installer pause/help-start, distinct-batch progress, independent/all-caller cancellation, late timeout/fault, non-cooperative callbacks, C/F saturation, malformed/enumeration-failing input/output, callback failures, every Set/Invalidate/Clear publication gap, per-key prefetch conflicts/token rotation, post-snapshot map mutation, sync/async consumers and retired-root/weight/expiry composition. Evidence resides in `BulkLoadingTests`, `BulkAdversarialTests`, `BulkTerminalRaceTests`, `BulkPublicationRevisionTests` and `FeatureCompositionTests`; none claims arbitrary wait-graph model checking.
