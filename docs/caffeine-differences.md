# Differences from Caffeine

Reference: pinned Caffeine v3.2.4. This is a contract comparison, not a speed ranking or compatibility certification. Four personalities, true bulk loading, adaptive W-TinyLFU, weight/size, expiry/TimerWheel, refresh, weak references, listeners, statistics and policy views are implemented; qualification remains separate. Version 0.2.0 is experimental, without an SLA; APIs may still change.

The legacy non-generic `LoadingCache.Create` and `LoadingCacheOptions` are removed,
an intentional source/binary break from published 0.1.0 and 0.1.0-alpha.1.2 packages. Use the typed
`CacheBuilder.Create<TKey, TValue>()` with explicit capacity; generic synchronous
`LoadingCache<TKey, TValue>` remains supported. See
[migration](semantics.md#migration-from-published-010-packages).

| Area                  | Local contract and practical difference                                                                                                                                                                                                                                                                                                                                      |
| --------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Loader admission      | No configured concurrency limit by default. Optional limits reject new flights without a queue; hits/joins continue. True bulk still requires pending-key/batch bounds, unlike Caffeine.                                                                                                                                                                                     |
| Fixed idle expiry     | Eligible lock-free TTI hits coalesce nearby touches with at most 1 ms timestamp error, without accumulation. A runtime shrink cannot recover a skipped access and can expire immediately; other touch paths remain exact. [Contract](semantics.md#expiration-and-refresh).                                                                                                   |
| Coarse fixed TTL      | Default-off `EnableCoarseExpirationChecks` requires `TimeProvider.System` and only affects eligible strong fixed-TTL value hits. Expiry detection can be late with no upper lag bound; task/quiet/policy, TTI, variable, weak/owned and refresh paths stay precise. A quiet miss can coexist with a coarse hit.                                                              |
| Idle maintenance      | Default-scheduler, built-in count-bounded/no-expiry caches without listeners may defer small idle write tails below `max(1,B/4)`. Pressure, threshold, active-owner and cleanup/forced boundaries or a non-sliding 1 ms target backstop drive progress. Other configurations signal immediately; the target is not an SLA. [ADR0013](adr/0013-bounded-write-maintenance.md). |
| Soft values           | No CLR equivalent to JVM SoftReference. Separately named opt-in GC-pressure trimming may sacrifice hit rate; observations can be stale and do not guarantee OOM prevention.                                                                                                                                                                                                  |
| Listeners             | Synchronous eviction outside locks before the owning step completes; bounded async removal may drop. Lock/visibility timing differs from Caffeine, and slow eviction callbacks delay their operation.                                                                                                                                                                        |
| Bulk/prefetch         | Neither is a multi-key transaction. Extras are absent-only and protected from newer same-key mutation. A 1,024-key active journal rotates on overflow, suppressing old extras but allowing new groups. Caffeine extras may overwrite concurrent mappings.                                                                                                                    |
| Cancellation/shutdown | Caller tokens cancel only their wait, even if all waiters leave. Timeout/clear/invalidation retain non-cooperative-work reservations. Shutdown cannot force user code to stop.                                                                                                                                                                                               |
| Mutable map           | .NET-style outside-lock retryable factories and exact-version atomic commits. Callback invocation count is not Caffeine compute parity. Pending async values can be replaced without blocking reads.                                                                                                                                                                         |
| Disposal              | Additional manual OwnedCache/CacheLease API waits for residency and leases to end. Ordinary raw values cannot safely be automatically disposed.                                                                                                                                                                                                                              |
| Statistics            | Local per-key request/per-backend load and timeout/refresh/removal definitions; not a field-for-field CacheStats substitute. Capacity evictions include size/weight/pressure, with expiry/collection separate.                                                                                                                                                               |
| Transport diagnostics | Internal accepted read-enqueue totals exclude rejected offers and derive from reservations minus unpublished slots. Settled totals are exact/saturating, in-flight snapshots weakly consistent; no new public `CacheStatistics` field.                                                                                                                                       |
| Adaptation            | Stable reactive policy plus selected tiny-cache fixes; not the complete newer master WindowClimber density controller.                                                                                                                                                                                                                                                       |

Weak keys/values use identity. Async weak values are illegal in both designs, not a unique missing feature here. CacheWriter was removed in Caffeine 3.x and is not a parity requirement. Reliable bounded writes are implemented; see ADR0013. Remaining engineering gaps are kept current in [release readiness](release-readiness.md), rather than duplicating stale platform/test counts here.
